## 1. Registry semantics (`sdk/translator/registry.go` 442, `types.go`, `format.go`, `formats.go`, `pipeline.go`; wrapper `internal/translator/translator/translator.go` 89)

- Format ids (`sdk/translator/formats.go`, `internal/constant/constant.go`): `openai` (chat completions), `openai-response`, `claude`, `gemini`, `codex`, `antigravity`, `interactions`. (`gemini-interactions` constant exists but no translator uses it.) `Format` is a string newtype, no normalization.
- Types: `RequestTransform func(model string, rawJSON []byte, stream bool) []byte`; `RequestEnvelopeTransform func(ctx, RequestEnvelope) RequestEnvelope` (Body, Model, Stream, Format, ModelInfo *registry.ModelInfo, ConfigurationUpdatesChanged); `ResponseStreamTransform func(ctx, model string, originalRequestRawJSON, requestRawJSON, rawJSON []byte, param *any) [][]byte`; `ResponseNonStreamTransform` same but returns `[]byte`; `ResponseTokenCountTransform func(ctx, count int64) []byte`; `ResponseTransform{Stream, NonStream, TokenCount}`.
- `Register(from, to, request, response)`: `requests[from][to] = request` (wrapped into an envelope fn that sets `req.Body = request(req.Model, req.Body, req.Stream)`), `responses[from][to] = response`. A nil request does not clear an earlier one; response is always overwritten. Only one pair uses `RegisterRequestEnvelope`: `openai-response -> antigravity` (`ConvertOpenAIResponsesRequestEnvelopeToAntigravity`, which receives ModelInfo), registered in addition to the plain `Register`.
- IMPORTANT direction asymmetry. Request lookup is `requests[from][to]` where from = CLIENT format, to = UPSTREAM format. Response lookup is `responses[to][from]` where the call is made as `TranslateStream(ctx, from=UPSTREAM, to=CLIENT, ...)`. Executors call `sdktranslator.TranslateStream(ctx, to /*upstream*/, responseFormat /*client*/, ...)`, so net effect: package registered as `Register(client, upstream, reqFn, {Stream,NonStream,TokenCount})` converts client->upstream on requests and upstream->client on responses. E.g. `Register(Claude, Gemini, ConvertClaudeRequestToGemini, {ConvertGeminiResponseToClaude,...})`. `TranslateTokenCount(ctx, from=upstream, to=client, count, raw)` uses the same `responses[to][from].TokenCount`.
- `TranslateRequestEnvelope(ctx, from, to, req)`:
  1. If a transform exists: `summary := thinking.ExtractTranslatedSummaryConfig(req.Body, from, to)` (extracted from the SOURCE body before translation); run transform; then `req.Body = thinking.ApplySummaryConfigForModel(req.Body, to, req.Model, summary)` (no-op when summary Unspecified); then plugin NormalizeRequest if hooks (ignore); `req.Format = to`.
  2. If NO transform exists: fallback passthrough. If `req.Model != ""` and body `model` != req.Model, `sjson.SetBytes(body,"model",req.Model)` (log on error). Otherwise the body is returned untouched with Format=to. Note same-pair-missing e.g. openai-response->openai-response, claude->claude, codex->* has no entry: pure passthrough + model rewrite.
- `HasRequestTransformer`, `HasResponseTransformer(from,to)` (reads `responses[from][to]`, true if any of the three fns non-nil; note `internal/translator/translator.NeedConvert` calls it with the registration orientation), `HasStream/NonStreamResponseTransformer`.
- `TranslateStream(ctx, from=upstream, to=client, ...)`: `stream = responses[to][from].Stream`. If nil and no hooks: `outputs = [][]byte{rawJSON}` (raw passthrough of the line). If non-nil: `outputs = stream(...)` (may be nil/empty slice meaning "emit nothing"). Special: if `*param` implements `ToolInputError() error` and it is non-nil, return outputs as-is (no raw fallback). With a native stream fn, empty outputs are NOT replaced by the raw body.
- `TranslateNonStream`: `fn = responses[to][from]`; if `fn.NonStream != nil` body = fn(...) (nil result -> returns nil); else raw body unchanged. Tool-input error on param -> nil.
- `TranslateTokenCount`: returns `fn.TokenCount(ctx,count)` if present else returns the `rawJSON` argument unchanged.
- Stream state: caller owns `var param any` per request and passes `&param` to every chunk call plus final non-stream; translators lazily allocate their state struct into `*param` on first call (nil check). `*param` may hold a non-pointer sentinel in trivial translators (e.g. `openai/openai/chat-completions` stores `bool true` after `[DONE]`). State is never shared across requests. `ToolInputError() error` optional interface is implemented by `common.ApplyPatchErrorState` (embedded by several state structs).
- Stream chunk contract: executors split upstream bytes into lines (bufio.Scanner, 50MB max) and feed ONE LINE per call (including `event: x` lines, blank lines, `data: {...}` lines, `data: [DONE]`). Translators strip `data:` prefix themselves (and generally ignore non-data lines, returning empty). Returned `[][]byte` items are complete outbound frames (many contain `event: ...\ndata: ...\n\n`, OpenAI chat chunks are often bare JSON that the handler frames as `data: ...`). Executors also call the stream fn once with `nil` rawJSON to initialize apply-patch state (`helps.InitializeApplyPatchStream`), so every Responses-target stream fn must tolerate empty input.
- `originalRequestRawJSON` = the client's original request body (executor passes `opts.OriginalRequest`, falling back to `req.Payload`: `helps.ApplyPatchOriginalRequest`); `requestRawJSON` = the translated (upstream-format) body actually sent (after thinking etc.). Response translators use them for tool-name maps, `model`, tools declarations, `stream_options`, etc.
- Executor pipeline order (e.g. `internal/runtime/executor/claude_executor_execute.go`): `TranslateRequest(client->upstream)` for both original payload and working payload (helps.TranslateRequestPairWithAPIKeyModelCompatibility...) -> set `model` -> `helps.ApplyRequestThinking` (-> `thinking.ApplyThinkingWith...`, section 6) -> provider payload rules/cloaking (out of scope) -> upstream call -> per-line `TranslateStream`.

## 3. JSON handling conventions (gjson / sjson) a Rust port must replicate

Translators are NOT struct-based. They treat bodies as byte strings, read with gjson and edit with sjson (`sjson.SetBytes` ~2540 call sites, `SetRawBytes` ~550, `DeleteBytes` ~94, `gjson.GetBytes` ~2300, `gjson.ParseBytes` ~360, `ForEach` ~250, `util.GetGJSONBytesNoCopy` (unsafe zero-copy alias of `gjson.GetBytes`) ~20). Output bytes are a function of the exact edit sequence, so byte-similar output requires a gjson/sjson-compatible raw-preserving engine, NOT serde_json::Value (which would sort or normalize keys/numbers/whitespace). Recommended: a small crate `rawjson` with `get(&[u8], path) -> Result{raw, kind, index}`, `set`, `set_raw`, `delete`, `for_each`, `valid`, mirroring the semantics below. Verified against `tmp/gopath/pkg/mod/github.com/tidwall/{gjson@v1.18.0,sjson@v1.2.5}`.

### 3.1 Templates and key order
- Most request/response objects are built from literal template strings, e.g. `[]byte(`{"model":"","messages":[]}`)`, then filled with `sjson.SetBytes`. Output key order = template order, then any newly set keys appended at the END of their object in call order. Setting an existing key replaces the value IN PLACE (position preserved). So key order is deterministic and identical to the Go code's call sequence; porters must follow the same sequence of edits, not "build a struct and serialize".
- Output is compact when built from compact templates, but raw sub-values copied via `SetRawBytes(out, path, part.Raw)` keep the client's original whitespace/formatting byte for byte (pretty-printed input stays pretty-printed inside). sjson never reformats the rest of the document.
- Arrays are usually grown with the append path `messages.-1` (35 sites use `.-1`), or assembled as `[][]byte` and joined (`common.JoinRawArray`, `common.SetRawArrayItems`, which writes `[` item `,` ... `]`) then set with `SetRawBytes`.
- `encoding/json` appears in 21 non-test files (list: gemini/interactions common, codex/claude request + web_search, codex/openai responses request, codex/interactions request, common/apply_patch_input + bytes, gemini/openai/responses request + signature_carrier, antigravity/{claude web_search, gemini request, interactions request, openai/responses request}, util/{claude_schema, gemini_schema, claude_tool_id}, cache/*). Wherever a `map[string]any`/`map[string]json.RawMessage` is marshaled, KEYS ARE SORTED ALPHABETICALLY, numbers round-trip via float64 for `any`, and HTML chars `<>&` are escaped to `<` etc. unless an encoder with `SetEscapeHTML(false)` is used (`util.marshalJSONNoHTMLEscape`, `common.SetStringWithoutHTMLEscape`). Notable: `util.NormalizeClaudeToolInputSchema` (sorted keys, RawMessage preserves values), `util.repairSchemaNode` / `normalizeMalformedSchemaObjects` (map[string]any: sorted keys, float64 numbers, no HTML escape), `common.DefaultSafetySettings()` marshaled via `sjson.SetBytes(path, []map[string]string)` (default Marshal: sorted keys `category`,`threshold`). Each of these sites must be ported with the same ordering semantics.

### 3.2 gjson reading semantics (v1.18.0)
- Path syntax actually used: dotted keys, numeric array indices (`messages.0.content`), `#` (array length, e.g. `contents.#`; ~25 sites), and `\.` escapes for keys containing dots (`util.escapeGJSONPathKey` escapes `.`, `*`, `?`; `translator/openai/gemini` has `escapeSjsonPathKey`). No `#(...)` queries, no modifiers (`@x`), no wildcards were found in translator sources. Port can restrict to key / index / `#` / escape.
- `Get` does NOT validate the document; it parses leniently from the start and returns the first match (duplicate keys: first wins; `Map()` last wins). Use `gjson.ValidBytes` (47 sites) when validity matters (`len(body)==0 || !valid -> "{}"` pattern in appliers).
- `Result{Type, Raw, Str, Num, Index}`. `Exists()` = `Type != Null || Raw != ""` (so JSON `null` exists; absent does not). `Raw` is the exact source substring (422 uses): this is how values are copied verbatim.
- `String()`: string -> unescaped `Str`; number -> `Raw` if it is an optional '-' followed only by digits, else `strconv.FormatFloat(Num,'f',-1,64)` (so `1.0` -> `1`, `1e3` -> `1000`, `2.50` -> `2.5`); true/false -> "true"/"false"; object/array -> Raw; null/absent -> "".
- `Int()`: Number -> `safeInt(Num)` (float64 exact integers under 2^53) else `parseInt(Raw)` else `int64(Num)`; String -> parse int from string (0 on fail); True -> 1; else 0. `Bool()`: String parsed with `strconv.ParseBool(lower)`, Number != 0. `Float()`/`Num` as float64.
- `Array()`: absent/null -> empty; non-array -> `[self]` (!); `Map()` returns a Go map (unordered; only ~15 uses, mostly `len(...)==0` emptiness checks). `ForEach` iterates in document order; for arrays key.Num is the index; a non-container value calls the iterator once with itself. `IsArray()/IsObject()` check the first byte of Raw.
- gjson unescapes `\uXXXX` incl. surrogate pairs in `Str`; invalid escapes are tolerated.
- Large payloads: `util.GetGJSONBytesNoCopy`/`ParseGJSONBytesNoCopy` are purely a perf aliasing of GetBytes/ParseBytes (results must not be retained). No semantic difference.

### 3.3 sjson writing semantics (v1.2.5)
- `SetBytes(json, path, value)`: value kinds: `string` -> JSON string (rule below); `[]byte` -> treated as a STRING value (stringified), not raw; `bool` -> `true`/`false`; all int/uint types -> decimal; `float32/64` -> `strconv.FormatFloat(v,'f',-1,64)` (never exponent; float32 widened to float64 first, so `0.1f32` prints `0.10000000149011612`); `nil`/struct/map/slice/other -> `encoding/json.Marshal` (HTML-escaped, sorted map keys); `sjson.Delete` sentinel -> delete.
- String escaping quirk (critical): `appendStringify` writes the string verbatim between quotes UNLESS it contains a byte `< 0x20`, `> 0x7f` (any non-ASCII), `"` or `\`; in that case it calls `encoding/json.Marshal(s)`. Consequences: (a) pure-ASCII strings without quote/backslash/control are NOT escaped at all, including `<`, `>`, `&`, `/`, DEL(0x7f); (b) any string that trips the rule is Marshal-encoded: `<`,`>`,`&` -> `<`,`>`,`&`; U+2028/U+2029 -> ` `/` `; invalid UTF-8 -> `�`; control chars -> `\n`,`\r`,`\t`, others `\u00XX` (Go >= 1.22: `\b`,`\f` as `\b`,`\f`); non-ASCII kept as UTF-8; `"`/`\` escaped. So `"a<b"` stays `"a<b"` but `"a<b\"c"` becomes `"a<b\"c"`. `common.SetStringWithoutHTMLEscape` (used by Responses translators and executors) bypasses this with an encoder having EscapeHTML(false) and then `SetRawBytes` (same escaping as Marshal minus `<>&`). The same appendStringify rule applies to the KEY name when sjson creates a new key.
- `SetRawBytes(json, path, raw)`: raw inserted verbatim, never validated (invalid raw produces invalid JSON). 
- Path resolution: simple paths only (parts split on '.', `\` escapes; chars `| # @ * ?` make the path "complex": `setComplexPath`, avoid). Existing target found (via gjson.Get) with `Index > 0` -> value replaced in place (bytes before/after untouched). Missing -> appended: into an object as `,"key":value` before the closing `}` (comma only if the object is non-empty); missing intermediates are created as `{}`; a numeric segment under a missing parent creates `[null,...,value]` (padding with `null` up to the index); `-1` appends to an existing array (creating `[v]` for a missing parent); a non-numeric, non-`-1` segment on an array errors ("cannot set array element for non-numeric key"). Setting an index beyond the array length pads with `null`.
- Root handling: empty/whitespace input -> starts from `{}` (or `[]` if the first segment is numeric); input whose root is not an object/array is REPLACED by `{}` silently (content lost); empty path -> error. Errors are generally ignored in translator code (`out, _ = sjson.SetBytes(...)`); on error the original bytes are returned unchanged.
- `DeleteBytes`: removes the key/element plus its adjoining comma (previous comma if last, else following comma); deleting an absent path is a no-op (returns input unchanged); `-1` deletes the last element; complex paths error. Deleting the last member leaves `{}` / `[]` (translators then often check `len(Map())==0` to remove empty parents, e.g. thinking appliers remove empty `output_config`).
- sjson never reorders, minifies, or re-escapes untouched content, and duplicate keys are not collapsed (only the first is edited).

### 6.1 Types (`types.go`)

Lookup: `registry.LookupModelInfo(modelID, provider)` = global registry per-provider info, else static catalog; returns a clone. ### 6.2 Suffix parsing (`suffix.go`)
- `ParseSuffix(model)`: last `(`; must END with `)`; `ModelName = model[:lastOpen]`, `RawSuffix` = inside. No validation (empty raw suffix `m()` is HasSuffix=true, raw "").
- `ParseNumericSuffix`: `strconv.Atoi`, reject negatives, leading zeros OK (`08192` -> 8192), overflow -> not ok. `ParseSpecialSuffix`: case-insensitive `none` -> ModeNone, `auto`/`-1` -> ModeAuto. `ParseLevelSuffix`: case-insensitive `minimal|low|medium|high|xhigh|max`.
- `parseSuffixToConfig(raw)` priority: special -> level -> numeric (0 -> ModeNone) -> unknown = empty config (treated as no config, debug log only).

### 6.3 `ApplyThinking` family (`apply.go`)
Entry points: `ApplyThinking(body, model, from, to, providerKey)`; `ApplyThinkingWithSummary(..., SummaryConfig)`; `ApplyThinkingWithSourceAndSummary(body, sourceBody, model, from, to, providerKey, summary, normalizedUpdatesChanged...)`; `ApplyThinkingWithModelInfo[AndSummary]` (exact ModelInfo, `modelInfoResolved=true`). All call `applyThinking`. Executors use `helps.ApplyRequestThinking` (`internal/runtime/executor/helps/model_capabilities.go`) and `helps.ApplyThinkingWithSourcePayload`.

Algorithm of `applyThinking(body, sourceBody, model, from, to, providerKey, resolvedModelInfo, modelInfoResolved, summary, normalizedUpdatesChanged)`:
1. `providerFormat = lower(trim(to))`, `openai-response` -> `codex`. `providerKey` defaults to providerFormat; `from` defaults to providerFormat. Suffix parse; `baseModel`. `modelInfo = resolved ?? LookupModelInfo(baseModel, providerKey)`.
2. Responses source config: if `from` is `codex`/`openai-response`, `sourceConfig = extractCodexUsageConfig(sourceRequest)` (last non-empty `input[].configuration_update.reasoning.effort`, else `reasoning.effort`), where `sourceRequest` is `sourceBody` unless plugin normalization changed updates.
3. If target is codex/xai and `!modelInfo.SupportConfigurationUpdate`: `stripConfigurationUpdates(body)` (remove `input[]` items with `type=="configuration_update"`, rewrite `input` raw). `nativeResponses = responseTarget && isResponsesFormat(from) && supportsUpdates`.
4. `applier = GetProviderApplier(providerFormat)`; unknown/unregistered -> return body unchanged. Registered names: `gemini, claude, openai, codex, antigravity, kimi, kimi-ai, kimi.ai, kimi.com, xai` (+ `interactions` registered by `provider/interactions`).
5. Guard: no suffix, responses source, body invalid JSON but source has config updates -> return body. If `nativeResponses` and no suffix -> return body untouched (debug log only).
6. `IsUserDefinedModel(modelInfo)` (nil modelInfo OR `UserDefined`) -> `applyUserDefinedModel`: config from suffix, else sourceConfig, else `extractThinkingConfig(body, from)`, else (if from!=to) `extractThinkingConfig(body, to)`; none -> `applySummaryConfigForProvider` only; `normalizeUserDefinedConfig` (Level -> Budget via `ConvertLevelToBudget` only when target is gemini/antigravity [claude excluded]); `applier.Apply(body, config, modelInfo)`; then re-apply summary unless fully disabled or nativeResponses. No validation (upstream validates).
7. `modelInfo.Thinking == nil` (model has no thinking support): if body has any thinking config or summary != Unspecified: strip (`stripResponsesEffort` for codex/xai, else `StripThinkingConfig(body, providerFormat)`); else passthrough.
8. Config source: suffix wins; else `sourceConfig`; else (if `modelInfoResolved` and sourceBody) `extractSourceThinkingConfig(sourceBody, from)`; else `extractThinkingConfig(body, providerFormat)`.
9. No config: apply summary only (`applySummaryConfigForProvider`), plus a Claude special case (`stripInferredClaudeSummaryActivation`) when cross-protocol summary-only request inferred adaptive thinking but the exact model is manual-budget only.
10. `mapConfiguredHighIntent` (only `modelInfoResolved` + Level mode + family mismatch): `xhigh` -> first supported of [xhigh,max,high]; `max` -> [max,xhigh,high].
11. `ValidateConfig(config, modelInfo, from, to, fromSuffix)`; error -> returns `(body, err)` (status 400).
12. `applier.Apply(body, *validated, modelInfo)`; then, unless fully disabled (Mode None, Budget 0, Level "") or nativeResponses, `applySummaryConfigForProvider(applied, ...)`.

Per-provider config extraction (`extractThinkingConfig(body, provider)`): 
- claude: `thinking.type=="disabled"` -> None; `adaptive|auto` -> only if `output_config.effort` string present (`none`->None, `auto`->Auto, else Level(lowercased)), else empty; else `thinking.budget_tokens` present: 0 -> None, -1 -> Auto, other -> Budget; else `type=="enabled"`: effort if present, else Auto.
- gemini/antigravity (prefix `generationConfig.thinkingConfig` or `request.generationConfig.thinkingConfig`): `thinkingLevel` / `thinking_level` first (`none`, `auto`, else Level), then `thinkingBudget` / `thinking_budget` (0 None, -1 Auto).
- interactions: `generation_config.{thinking_level,thinkingLevel,thinking_config.*,thinkingConfig.*}` levels then budgets (same mapping, lowercased/trimmed).
- openai: `reasoning_effort` (`none` -> None, else Level raw string, not lowercased). codex/xai: `reasoning.effort`. kimi*: `thinking.type` disabled -> None; enabled without `thinking.effort` -> empty; `thinking.effort` (lowercased; `none`, `auto`, else level); explicit thinking object without effort -> empty; else legacy `reasoning_effort`.
- Usage-logging helpers: `ExtractReasoningEffort(body, provider, model)`, `ExtractTranslatedReasoningEffort(body, provider)` produce canonical labels (`none|auto|<level>|budget-derived level`).
- `StripThinkingConfig(body, provider)` (`strip.go`) deletes: claude `thinking`, `output_config.effort` (+ drops empty `output_config`); gemini `generationConfig.thinkingConfig`; antigravity `request.generationConfig.thinkingConfig`; interactions 8 `generation_config.*` thinking keys; openai `reasoning_effort`,`reasoning`; kimi `reasoning_effort`,`thinking`; codex/xai `reasoning`.

### 6.4 Validation/clamping (`validate.go`, `convert.go`)
- Conversions: `ConvertLevelToBudget`: none 0, auto -1, minimal 512, low 1024, medium 8192, high 24576, xhigh 32768, max 128000. `ConvertBudgetToLevel`: <-1 invalid; -1 auto; 0 none; <=512 minimal; <=1024 low; <=8192 medium; <=24576 high; else xhigh. `MapToClaudeEffort(level, supportsMax)`: minimal->low; low/medium/high same; xhigh|max -> max if supportsMax else high; auto -> high. `HasLevel`.
- Capability (`detectModelCapability`): nil modelInfo Unknown; `Thinking==nil` None; Min>0||Max>0 and Levels -> Hybrid; budget only -> BudgetOnly; levels only -> LevelOnly.
- Family helpers: gemini family = {gemini, antigravity}; openai family = {openai, openai-response, codex}; `isSameProviderFamily(a,b)` = equal or same family. `modelFamilyMismatch` = modelInfo.Type nonempty and from/to not same family as Type. `allowClampUnsupported` = target has level support and (families differ or modelFamilyMismatch). `strictBudget` = !fromSuffix && from known && same family && !modelFamilyMismatch.
- `ValidateConfig` steps: no support -> only ModeNone allowed else `THINKING_NOT_SUPPORTED`. BudgetOnly: Level -> Budget (`UNKNOWN_LEVEL` if unmapped; `auto` level kept). LevelOnly: Budget -> Level via `ConvertBudgetToLevel` then `clampLevel`. Normalize: Level none -> Mode None; Level auto -> Mode Auto (-1); Budget 0 -> None. If model has Levels and Level mode: unsupported level -> clamp when allowed else `LEVEL_NOT_SUPPORTED` with message `level "x" not supported, valid levels: a, b`. Strict budget range check -> `BUDGET_OUT_OF_RANGE` message `budget N out of range [min,max]` (also zero when !ZeroAllowed). Auto with `!DynamicAllowed` -> `convertAutoToMidRange` (levels-only -> Level medium; else Budget=(Min+Max)/2, or None if mid<=0 and ZeroAllowed, or Min if mid<=0). Claude + None keeps Budget 0/Level "". Else clamp budgets (`clampBudget`: -1 passthrough; 0 not allowed -> Min; below Min -> Min (0 stays if ZeroAllowed); above Max -> Max; Min==Max==0 -> unchanged). ModeNone on a model that cannot be disabled and has Levels -> `Level = Levels[0]`.
- `clampLevel`: nearest supported level by index in [minimal,low,medium,high,xhigh,max], ties prefer lower.

## 12. Porting hazards (summary)

1. Raw-preserving JSON: do not round-trip through a DOM. Reproduce sjson's in-place replace, end-of-object append, `-1` append, null padding, comma removal, and the "string escaped only if it contains control/non-ASCII/quote/backslash" rule (section 3.3). HTML-escape behavior differs between `sjson.SetBytes(string)` (conditional) and `SetStringWithoutHTMLEscape` (never escapes `<>&`).
2. Spots that sort keys / use float64: all `encoding/json` map marshals listed in 3.1, and `Result.String()` number reformatting for non-integer numbers. Large ints > 2^53 survive only as `Raw` or via `Int()`'s raw parse.
3. Direction asymmetry in the registry (`responses[to][from]`): port as a single table keyed (client, upstream) and look up with client/upstream explicitly; `NeedConvert`/`HasResponseTransformer` take the registration orientation.
4. Stream fns are line-oriented state machines with lazily created state in `*param`; empty returns mean "swallow"; `ToolInputError()` optional interface short-circuits fallback.
5. Request-level summary extraction/application wraps every request transform in the registry (thinking::summary), and thinking application is a separate later step (`ApplyThinking*`) that depends on suffix parsing, the model registry and provider appliers.
6. Global/shared state: signature cache (+ enable/strict atomics), antigravity reasoning replay cache (via gemini/openai/responses trailing signatures), model registry, apply-patch tool registry, atomic id counters, `time.Now()`.
7. Protobuf wire parsing for signature validation (varint/bytes fields, CAIS/CAQS envelopes), standard base64 (padded) decode/encode, entropy ratio over decoded bytes (Grok/Kimi).
8. Go-specific behaviors to mirror: `strings.TrimSpace` (Unicode whitespace), byte-length (not char) truncation at 64 for tool names (can split UTF-8 only if non-ASCII survives; sanitizers replace non-ASCII with `_` first for Claude/Gemini name sanitizers), `strconv.Atoi` rules, map iteration randomness (translators that range over maps must sort; check per-package notes), `sort.Slice` instability where used.
